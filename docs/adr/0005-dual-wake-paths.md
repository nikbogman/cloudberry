# Dual independent wake paths: Pi proxy and Pi API

_Amended by [ADR-0011](0011-server-owns-workload-routing.md) (Pi proxy no longer reverse-proxies per-service) and [ADR-0012](0012-auto-wake-proxy-calls-control-pi-api.md) (the two paths are no longer independent — the Pi proxy now calls the Pi API's `/wake` instead of sending its own WoL packet). What survives here: the two remain distinct triggers, each still driving its own caller-facing behavior._

Two separate mechanisms send Wake-on-LAN packets for the same physical action, and neither calls the other. Caddy's Pi proxy plugin reverse-proxies every Docker service on the main server and wakes it transparently on any incoming request — this serves ordinary access to hosted services (Immich, AI agents, etc.) without the user ever visiting the UI. The Pi API's Wake action is a separate, deliberate trigger from the UI's Wake button, used for explicit control and to drive the UI's reachability display. We kept these independent rather than routing one through the other because they serve different callers (arbitrary service traffic vs. the control panel) and coupling them would make the simpler one (the Pi proxy) depend on the control plane's availability.
