# Direct browser-to-API calls, no Pi-side relay

The browser calls the Pi API and the Server API directly; there is no server-side relay between the two devices. We considered routing all Control UI traffic through the Pi (so the browser only ever talks to one origin), but rejected it: a relay would require the Server API to trust a forwarded identity claim from the Pi rather than verifying the real caller's `Tailscale-User-Login` header itself — a new trust relationship the direct-call model avoids entirely. The cost is that the Server API needs a CORS allow-list entry for the Control UI's origin.
