# Server owns all workload routing, the Pi's proxy carries no per-workload knowledge

The Pi's Caddy config no longer lists individual workload services (Immich, AI agents, etc.) or their container ports. Instead it has a single `handle_path /server*` route (prefix stripped) that blindly reverse-proxies to one fixed address, `{$MAIN_SERVER_HOST}:{$SERVER_PROXY_PORT}`, wrapped in the existing `auto_wake_route`/`wake_on_lan` snippet unchanged. Deciding which path reaches which container (`/immich`, `/agents`, ...) becomes entirely the main server's own reverse proxy's job — a piece of infrastructure that stays outside pyinfra's management, exactly like the Docker Compose stacks it fronts (`spec.md`'s existing scope boundary), to be built manually if/when needed. We considered keeping today's per-workload `route_port`/`upstream_port` pairs in `deploy_caddy.py`'s `WORKLOADS` list, and a middle option where the Pi and the server share one port number per workload by convention — both rejected because either leaks the server's internal Docker topology into the Pi's pyinfra config, or still requires a pyinfra redeploy of the Pi's Caddy every time a workload is added. We also considered host-based (subdomain) routing instead of path-based, and rejected it since it would need a separate `tailscale serve` mapping per workload; path-based matches the same-origin, path-routed pattern this repo already uses for the Control UI/Pi API. The cost: the Pi can no longer distinguish "server is asleep" from "server is awake but its own proxy is down" — collapsing to one upstream means one failure signal now covers every workload, a wider blast radius than today's per-workload checks. This changes what ADR-0008's fully-templated Caddyfile actually contains (one static route instead of one per workload) without reversing that decision itself — the Caddyfile stays 100% pyinfra-owned, nothing hand-edited on the device. It also supersedes the "reverse proxy in front of every Docker service" description of the Pi proxy in `CONTEXT.md` and in ADR-0005's prose — ADR-0005's actual decision (keeping the two wake paths independent) is unaffected.
